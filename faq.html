Getting started

Is Scanline Classic free?

Yes. Scanline Classic is an open-source project and is available for free. You can download it from the project repository. Some of the presets may already be included in your RetroArch installation.

What do I need to use Scanline Classic?

You need RetroArch with Slang shader support. See the project documentation for installation and usage guidance.

Compatibility

Can Scanline Classic be used with any system?

Scanline Classic is designed to work with RetroArch, which supports a wide range of systems. Any preset can be applied to any system supported by RetroArch with Slang shader support. However, the visual result will vary depending on the preset used. For best results, choose a preset that matches the system, region, and intended video connection of the content you want to play. If a preset is not available for your specific combination, you may open an issue on the project repository. There are other programs beyond RetroArch that support Slang shaders, but RetroArch is the only current officially supported platform at this time.

Does Scanline Classic work with interlaced content?

Yes. When we create a preset for a particular system, we test it on all native output modes of that system to the extent possible, including interlaced modes. This ensures that the preset works correctly with interlaced content.

Does Scanline Classic support high-resolution content and upscalers?

Not primarily. Scanline Classic is focused on recreating the look of classic displays and video connections. Emulators that render content at a size higher than the orignal system resolution are not tested for accuracy or compatibility with these presets.

Do I need any special hardware?

Scanline Classic requires a relatively fast video card compared to other shaders. However, most presets can run full speed on recent integrated graphics and handhelds.

Displays

Does Scanline Classic work with HDR displays?

Yes. Scanline Classic is designed specifically to work with HDR displays and has a full HDRR pipeline to maintain better color reproduction and dynamic range. If you have an HDR-compatible video card and display, we recommend enabling HDR mode in your OS settings and RetroArch to take full advantage of this feature.

Does Scanline Classic work with SDR displays?

Yes. Scanline Classic is compatible with SDR displays as well. The shader will adapt to the display's capabilities automatically.

Do I need to calibrate my display?

No. Scanline Classic is designed to work well with both professional and consumer displays. Calibration is recommended, but you may set your monitor up as you prefer and still achieve good results.

Presets

Why are there so many presets?

Different systems, regional versions, video connections, and displays can produce different pictures. The presets provide starting points for many of those combinations, so you can choose a look that fits what you want to play. It isn't necessary to try them all.

Why are there multiple presets for the same system?

A system may have regional variants and may be shown through different video connections, such as RF, composite, S-Video, or RGB. Presets can also represent different kinds of displays, such as consumer televisions and professional monitors. These choices affect the picture, so try the version that matches the experience you want.

Which preset should I start with?

Look for your system and region, then try a consumer or professional preset. If there are different connection options, choose one that interests you and compare it with the others. The best starting point is the one you enjoy.

Can I adjust the look?

Yes. Presets are starting points, and shader parameters let you customize the picture. See the project documentation for details.

Other projects

Are there other projects similar to Scanline Classic?

Yes, there are other projects that aim to recreate the look of classic displays and video connections. For a list of projects we recommend exploring, see the resources page.

Accuracy and design

Is Scanline Classic focused on accuracy?

Accuracy is one consideration, but reproducing a display involves choices about which display, connection, signal path, and hardware revision are being represented, coupled with balancing performance and visual appeal. We intentionally explore a range of historical technologies and presentation styles rather than targeting a single universal result to reflect this reality.

Are all shader functions in Scanline Classic based on real hardware behavior?

Not necessarily. While many functions are inspired by real hardware and video signal behavior, some are visual-based interpretations or approximations to achieve a desired effect. The goal is to capture the character of classic displays rather than to perfectly replicate every technical detail. Many implementation details are unknown or difficult to implement with real-time shaders, so compromises are made to balance overall quality.

Why doesn't Scanline Classic try to reproduce a single "correct" CRT?

The "professional" presets represent the idealized vision of a high-quality, well-calibrated display from the era, using the best officially supported connection method of each system. These presets can be identified by their lack of a connection suffix, e.g. sfc.slangp. However, we don't want to present these as being the only choice or any more correct than the other presets, so alternative presets are given equal placement in the shader file hierarchy.

How are shaders and presets developed?

The first thing we do when developing a preset is to research the target system and attempt to iterate all possible output modes and reconcile their timing with the system's native source resolutions and refresh rates (controlled by the RetroArch core). Once timing is established, we verify the output connections officially supported by the manufacturer using manuals, technical documents, marketing materials, and other reliable sources. This helps ensure that the preset accurately represents the intended video signal path. Only after this do we determine if the current shader implementations are sufficient to faithfully represent the system's behavior. If not, we develop new shaders or modify existing ones to achieve the desired result. We then consider the display characteristics, considering possible display types that would have been used with the system and representative of its time. With correct timing, connection, and display characteristics established, we can implement a rough first-pass version of the preset. After this, we refine the preset further by studying more technical details, such as schematics, block diagrams, part data sheets, dev kit APIs, and anything else that can inform an accurate representation of the system's video output. Presets are continually updated as shaders are improved and new information becomes available.

Source and builds

Why does the source code have a build process?

The build process generates the full set of presets and ensures that all shader files are correctly compiled. This allows the project presets to be declared through a data-driven architecture. The actual .slangp files are produced as part of this build process. See the project documentation for more details.

Why does the source code build more presets than my RetroArch installation?

The source code includes all available presets, but your RetroArch installation may only include a subset. This is done to reduce the initial download size and to provide a curated set of presets for most users. You can manually add additional presets after downloading and building from source.

Are there any other differences between the source code and the RetroArch installation?

Yes. The source code also includes lossless texture files in PNG format. The RetroArch installation uses JPEG-compressed textures to save space and reduce download size. Aside from those differences, the functionality and visual output should be consistent between the source code and the RetroArch installation.

Community and licensing

Where can I ask questions or discuss the shader?

Visit the Scanline Classic Libretro forum thread.

Can I contribute to Scanline Classic?

Yes. Contributions are welcome, whether it's reporting issues, suggesting improvements, or submitting code changes. We kindly ask that you open an issue or discussion on the project's repository before submitting a pull request. Please refer to the project documentation for guidelines on contributing and the preferred workflow for submitting changes.

Why GPLv3?

Scanline Classic is licensed under the GNU General Public License version 3 (GPLv3) to ensure that the project remains free and open-source. This license allows anyone to use, modify, and distribute the software, while also requiring that derivative works are shared under the same terms. The choice of GPLv3 helps protect the project's openness and encourages community contributions.

Why not a more permissive license?

The choice of GPLv3 over more permissive licenses is intentional to ensure that the project and all contributions remain free and open-source. If you have a need for a different licensing arrangement, please contact the project maintainers to discuss potential options.

Can I buy you a coffee?

That's very kind of you, but the project does not accept direct donations. Your support through contributions, spreading the word, or participating in the community is greatly appreciated.
